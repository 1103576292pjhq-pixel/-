# 01 NPU 基础：这道题到底在做什么

## 先从一个小矩阵乘开始

假设：

```text
A = [1 2]      B = [5 6]
    [3 4]          [7 8]
```

那么：

```text
Y[0][0] = 1*5 + 2*7 = 19
Y[0][1] = 1*6 + 2*8 = 22
Y[1][0] = 3*5 + 4*7 = 43
Y[1][1] = 3*6 + 4*8 = 50
```

每个输出元素本质上都是一串“乘法再相加”。这就是 MAC：`Multiply-Accumulate`，乘加。

## 为什么 NPU 适合做这件事

CPU 很灵活，适合复杂控制和分支；GPU 擅长大规模并行；NPU 更专门，常把矩阵乘、卷积、低精度数值格式做成固定硬件路径。这样做的价值是：

- 同一类 MAC 可以并排放很多份，吞吐更高。
- 数据格式更短，搬运和存储更省。
- 控制更简单，能效通常更好。

本项目不是完整 NPU 芯片，而是一个 NPU 里面可能出现的“矩阵乘计算阵列核心”。

## PE、列单元和阵列

可以先把 PE 理解成一个小计算工位。很多 PE 排起来，就形成阵列。

本项目里最重要的两层是：

```text
llmt_col          : 一列 dot32 + FP32 accumulator
mx_array_32x16   : 16 个 llmt_col 并排
```

示意图：

```text
             B0       B1                 B15
             |        |                  |
A block -> [col0]   [col1]   ...       [col15]
             |        |                  |
           Y col0   Y col1              Y col15
```

## 为什么要低精度

如果所有输入都用 FP32，硬件代价会很高：

- 乘法器更大。
- 存储空间更大。
- 片上搬运和功耗更高。

大模型推理常用低精度来换取更高吞吐。本题使用 MXFP8：每个元素 8 bit，但每 32 个元素共享一个 scale，兼顾存储效率和动态范围。

## 这道题的正式目标

赛题核心目标可以写成：

```text
Y = A * B
A/B: MXFP8
Y  : FP32
阵列: 32x16
```

不要把它说成“完整后端芯片已实现”。当前仓库交付的是前端 RTL、验证证据、Python golden model、报告和后端 handoff 模板。

## 常见错误

- 把 NPU 说成“更快的 CPU”。NPU 的关键是专用矩阵计算路径。
- 把 MAC 当成单独一个乘法。MAC 包含乘法和累加。
- 把 `llmt_col` 当成完整矩阵乘法器。它只是一列 dot32/accumulate 单元。

## 用自己的话复述

“这个项目做的是一个适合 NPU 的矩阵乘计算阵列。矩阵乘由很多 MAC 组成，硬件把 16 个列单元并排，每个列单元一次处理 32 个 K 方向元素，并把结果累加成 FP32。”
